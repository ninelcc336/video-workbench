# 项目与本地工作区导航简化规格

Status: wontfix

> 此规格已被 `.scratch/fixed-local-project-library/spec.md` 替代。产品不再向用户暴露本地工作区或目录切换能力。

## Problem Statement

当前编辑页同时暴露编辑项目和本地工作区两个层级，用户容易把“项目”和“存储容器”误认为同一种对象。工作区切换、项目切换、自动保存和错误恢复的边界也不够清晰：打开一个没有项目或项目损坏的工作区时，用户不能明确知道当前状态，错误情况下还可能误以为空项目已经替换了原有编辑内容。

## Solution

把编辑页收敛为“选择和编辑编辑项目”的工作空间：顶栏直接显示当前编辑项目的 Radix Select，项目的新建、打开、重命名和删除收进项目管理入口；本地工作区只以只读名称展示，切换、创建和打开工作区放到启动页或工作区设置入口。

应用启动时自动尝试打开上次成功的本地工作区，但只有工作区和当前项目都能正常读取时才进入编辑页。首次启动没有最近工作区时，显示启动页，要求用户明确创建或打开本地工作区。工作区成功打开但没有编辑项目时，显示空工作区状态，不静默创建项目。

## User Stories

1. 作为首次使用者，我希望看到清晰的启动状态，以便知道需要先选择或创建本地工作区。
2. 作为首次使用者，我希望创建本地工作区时明确指定目录，以便知道视频素材、编辑项目和导出结果保存在哪里。
3. 作为回访使用者，我希望应用自动打开上次成功的本地工作区，以便快速继续工作。
4. 作为回访使用者，我希望上次工作区无法读取时看到错误和恢复入口，以便不会被静默带入空状态。
5. 作为使用者，我希望在启动页看到最近使用的本地工作区，以便快速选择熟悉的工作环境。
6. 作为使用者，我希望最近工作区选项同时显示名称和路径辅助信息，以便区分同名目录。
7. 作为使用者，我希望从设置入口打开其他本地工作区，以便在不同内容目录之间切换。
8. 作为使用者，我希望可以创建一个尚不存在的本地工作区，以便开始新的内容项目。
9. 作为使用者，我希望当前本地工作区名称以只读信息展示，以便理解它不是另一个编辑项目。
10. 作为使用者，我希望编辑页顶栏直接显示当前编辑项目名称，以便知道正在编辑哪个项目。
11. 作为使用者，我希望通过一个项目选择器打开其他编辑项目，以便不必理解文件系统结构。
12. 作为使用者，我希望项目选择器支持键盘操作和可访问名称，以便不依赖鼠标完成项目切换。
13. 作为使用者，我希望项目列表按最近更新时间排序，以便优先找到最近编辑的项目。
14. 作为使用者，我希望在编辑页新建编辑项目，以便继续留在当前本地工作区中工作。
15. 作为使用者，我希望新建编辑项目时必须填写名称，以便项目不会以隐含名称出现。
16. 作为使用者，我希望项目名称自动去除首尾空格，以便避免意外创建带空格的项目。
17. 作为使用者，我希望项目名称允许中文、英文、数字、空格和常见标点，以便使用自然语言命名项目。
18. 作为使用者，我希望项目名称不能包含路径分隔符、空名称、`.` 或 `..`，以便项目文件不会越出本地工作区。
19. 作为使用者，我希望大小写不同但实际冲突的项目名称被视为重复，以便 Windows 文件系统不会出现不稳定的项目列表。
20. 作为使用者，我希望在编辑页重命名当前项目，以便修正项目名称而不丢失编辑内容。
21. 作为使用者，我希望重命名失败时原项目仍可继续编辑，以便名称冲突不会破坏当前项目。
22. 作为使用者，我希望删除当前项目后自动打开其他最近编辑的项目，以便继续工作。
23. 作为使用者，我希望删除最后一个项目后看到空工作区状态，以便明确知道工作区中没有编辑项目。
24. 作为使用者，我希望删除编辑项目不会删除共享视频素材，以便其他项目仍能继续引用这些视频素材。
25. 作为使用者，我希望删除仍被项目引用的视频素材时操作被阻止，以便不会破坏编辑项目。
26. 作为使用者，我希望复制编辑项目不会出现在产品中，以便项目管理保持简单且不引入额外生命周期。
27. 作为使用者，我希望切换编辑项目前只在存在未保存编辑时收到提示，以便已保存状态下不会被重复打扰。
28. 作为使用者，我希望自动保存进行中或失败时看到继续切换和返回编辑两个选择，以便决定是否承担数据风险。
29. 作为使用者，我希望取消切换后项目选择器恢复原值，以便界面状态与当前项目一致。
30. 作为使用者，我希望取消工作区切换后设置面板仍保持打开，以便可以重新选择工作区。
31. 作为使用者，我希望确认切换工作区后重新加载编辑项目，以便编辑器不会继续展示旧工作区的项目。
32. 作为使用者，我希望切换工作区后重新加载视频素材，以便素材库和视频预览来自正确的本地目录。
33. 作为使用者，我希望切换工作区后重新加载个人预设，以便只使用当前工作区的个人资产。
34. 作为使用者，我希望切换工作区后重新加载视频模板，以便只使用当前工作区的时间轴布局资产。
35. 作为使用者，我希望工作区打开失败时当前编辑项目继续可见，以便错误不会替换正在编辑的内容。
36. 作为使用者，我希望工作区失败提示提供重试入口，以便在临时目录或服务错误恢复后再次打开。
37. 作为使用者，我希望工作区失败提示提供返回编辑入口，以便放弃切换并继续当前工作。
38. 作为使用者，我希望项目损坏时可以明确选择从最近备份恢复，以便恢复行为不会覆盖原始文件。
39. 作为使用者，我希望工作区中没有项目时看到“暂无编辑项目”，以便理解这是空状态而不是加载失败。
40. 作为使用者，我希望从空工作区状态新建第一个编辑项目后进入编辑页，以便流程从空状态自然进入编辑状态。

## Implementation Decisions

- 使用 `@radix-ui/react-select` 实现编辑项目选择器和工作区导航选择器；属性面板和导出设置等普通表单选择继续使用原生选择控件。
- 使用已有的 Radix Alert Dialog 实现未保存切换确认，不使用浏览器原生确认框。
- 项目选择器始终显示当前项目名称；项目管理操作单独收进项目管理入口。
- 工作区设置入口只显示当前工作区只读名称，并负责最近工作区、打开本地工作区和创建本地工作区。
- 工作区选择项显示工作区名称和路径辅助信息；当前顶栏只显示工作区名称。
- 启动流程优先尝试最近成功工作区；首次启动没有最近工作区时必须由用户明确选择创建或打开。
- 空工作区是合法的产品状态，不能通过读取失败、网络失败或项目损坏路径静默伪造空项目。
- 新建编辑项目需要用户提供名称。名称 trim 后校验，禁止空值、路径分隔符、空字节、`.` 和 `..`，并按不区分大小写判断唯一性。
- 重命名编辑项目是项目标识变更：项目文件原子移动，项目快照、视频素材引用和特效片段保持不变。
- 移除复制编辑项目的 UI、交互、接口和验收范围，项目生命周期只保留新建、打开、重命名和删除。
- 删除编辑项目不级联删除视频素材；删除视频素材前扫描所有编辑项目引用，仍被引用时拒绝删除。
- 项目按最近更新时间排序。删除当前项目后打开最新的其他项目，没有其他项目则进入空工作区状态。
- 自动保存状态为进行中或失败时，切换项目或工作区前显示确认；已自动保存状态下直接切换。
- 取消切换必须恢复选择器原值；取消工作区切换时保留工作区设置面板和当前编辑项目。
- 工作区切换必须在候选工作区完成目录初始化和当前项目可读取校验后，才替换服务端当前工作区。
- 切换成功后重新加载当前编辑项目、视频素材、个人预设和视频模板；读取失败保留旧编辑界面并提供恢复动作。
- 前端状态通过 `App` 协调启动、空状态、编辑状态和错误恢复；持久化行为通过现有 `WorkspaceAdapter` seam 验证。

## Testing Decisions

- 测试只验证用户可观察行为、持久化结果和跨边界引用关系，不绑定 Radix 内部 DOM 实现细节。
- 在 `App` 最高层 seam 覆盖启动页、空工作区、项目选择、工作区选择、未保存确认、取消恢复和错误恢复。
- 在 `WorkspaceAdapter` seam 覆盖候选工作区原子切换、项目名称校验、项目 CRUD、空项目状态、备份恢复和共享视频素材引用保护。
- 在现有 Playwright 入口覆盖真实启动、Radix 选择器导航、未保存提示取消/继续、工作区切换失败保留当前编辑和空工作区入口。
- 组件测试覆盖项目选择器、工作区设置入口、未保存确认对话框和空工作区状态的可访问名称与键盘交互。
- 相关测试应先以失败用例描述新行为，再实现代码；完成后运行全量测试、类型检查、生产构建和浏览器验收。

## Out of Scope

- 不实现复制编辑项目。
- 不实现云端工作区、账号同步或跨设备项目同步。
- 不把本地工作区扩展为完整文件管理器。
- 不替换属性面板和导出设置中的所有原生选择控件。
- 不改变视频素材与编辑项目之间的共享引用模型。
- 不改变视频片段的编辑项目时间基准、首个视频素材确定画布比例和帧率的规则。
- 不增加完整剪辑软件能力、自动字幕或复杂媒体编排能力。

## Further Notes

- 本规格使用 `CONTEXT.md` 中的“本地工作区”“编辑项目”“视频素材”“视频模板”“个人预设”等领域词汇。
- 工作区切换与编辑项目切换必须始终区分：前者改变存储边界，后者只改变当前编辑对象。
- Radix 组件用于交互一致性和可访问性，产品验收仍以用户看到的名称、状态、提示和恢复行为为准。
