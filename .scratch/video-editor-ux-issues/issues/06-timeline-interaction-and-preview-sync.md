# 编辑时间轴的操作反馈不足，编辑结果没有及时联动预览

Category: bug  
Status: resolved

## Summary

补齐时间轴与编辑器状态、预览画面之间的交互反馈，让用户能够通过时间轴完成定位、选择、移动、裁剪和删除，并立即看到结果。

## Current behavior

用户反馈下方编辑轨道几乎没有互动。现有时间轴虽然具备标尺点击、片段选择、片段拖动、左右边缘调整和 Delete 删除的回调，但模板拖放辅助函数没有在时间轴组件上形成完整的放置链路；同时播放头只更新页面数字，未驱动预览 Player。

## Desired behavior

时间轴应成为编辑项目的可靠操作面：用户可以看到所有片段的时间范围，点击定位，选择后移动或调整持续时间，拖动模板到指定位置，并在每次操作后立即看到预览和参数面板的对应变化。

## Acceptance criteria

- [x] 点击时间标尺或时间轴空白位置可以定位到对应帧，播放头位置和预览画面同步。
- [x] 点击视频片段或特效片段后，选中状态、右侧参数面板和预览选区正确更新。
- [x] 拖动片段可以改变起始帧，拖动左右边缘可以改变持续时间，且不会产生负帧或零时长。
- [x] 从模板库拖到时间轴指定位置会创建对应的特效片段，并使用放置位置作为起始帧。
- [x] 删除选中片段后，时间轴、预览和参数面板都不再保留该片段。
- [x] 时间轴操作不会破坏现有撤销、重做和自动保存行为。

## Out of scope

- 多视频轨道和复杂剪辑工具。
- 关键帧编辑。
- 特效片段分配多个轨道的问题；该问题单独记录在 issue 07。

## Related implementation concepts

- `Timeline` / `TimelineClip`：时间轴显示和鼠标手势转换。
- `EditorCommand`：项目片段移动、删除和参数更新命令。
- `createEffectClipFromTemplate` / `getDropFrame`：模板拖放创建和位置换算。
- `EditorPage.currentFrame`：时间轴、模板添加和预览之间的共享播放头。

## Initial triage notes

已确认时间轴并非完全没有交互，但现有能力集中在回调和最终 mouseup 提交，缺少完整的模板放置链路与 Player 同步。因此需要通过浏览器复现，分别确认用户所说的“几乎没有互动”具体是按钮不可用、拖拽无反馈，还是操作后预览没有变化。
