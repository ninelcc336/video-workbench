# 实时预览缺少播放、暂停和播放头同步

Category: enhancement  
Status: resolved

## Summary

为实时预览补充播放和暂停控制，并让 Player 当前帧、时间轴播放头、时间读数和特效添加位置保持同步。

## Current behavior

预览区域只渲染 Remotion Player，没有面向用户的播放或暂停操作。页面虽然维护了 `currentFrame`，但该状态目前只被时间轴读写，未传入 Player 控制当前帧，也没有监听 Player 的帧变化。

## Desired behavior

用户可以在预览区域播放、暂停并拖动或点击时间轴定位。播放时视频、特效动画和时间轴播放头同步推进；暂停后画面保持当前帧。用户在播放头位置添加特效时，特效片段从当前帧开始。

## Acceptance criteria

- [ ] 预览区域提供清晰可用的播放和暂停控制，并能反映当前播放状态。
- [ ] 播放时当前帧、时间轴播放头和时间读数持续同步。
- [ ] 暂停后当前帧保持不变，重新播放从暂停位置继续。
- [ ] 点击时间轴标尺或移动播放头后，预览跳转到对应帧。
- [ ] 播放头位置添加特效时，新增特效片段的 `fromFrame` 等于当前帧。
- [ ] 播放超出项目时长时不会访问无效帧，也不会让时间轴和 Player 失步。

## Out of scope

- 音频剪辑、音量控制和音频波形编辑。
- 倍速、循环播放和逐帧高级控制，除非后续需求明确提出。
- 改变 Remotion 预览与导出共用组合定义的原则。

## Related implementation concepts

- `PreviewPlayer`：需要暴露或接收 Player 的控制接口。
- `EditorPage.currentFrame`：页面级播放头状态。
- `Timeline.onSeekFrame`：时间轴定位入口。
- `EditorComposition`：应继续作为预览视觉内容的唯一来源。
