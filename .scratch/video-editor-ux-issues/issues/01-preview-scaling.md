# 实时预览没有利用可用空间，导入视频画面过小

Category: bug  
Status: needs-triage

## Summary

让实时预览根据中间预览区域和编辑项目画布比例自适应显示，避免大面积空白中只出现一个难以辨认的小视频框。

## Current behavior

中间区域占据了较大空间，但实际预览容器采用固定的竖屏比例和高度上限。用户导入视频后，画面显示过小，难以看清视频内容和叠加的特效。

现有实现已经通过 Remotion Player 使用编辑项目的宽高，但预览外壳仍然固定为 `9 / 16`，且没有明确根据项目设置计算可用尺寸。

## Desired behavior

预览画面应在中间区域内尽可能放大，同时保持编辑项目的宽高比、不变形、不溢出；画布上的特效位置和选区也必须与视频画面保持一致。

## Acceptance criteria

- [ ] 导入默认竖屏项目的视频后，预览画面填充可用区域，画面主体清晰可辨。
- [ ] 预览容器的宽高比来自编辑项目设置，而不是写死为 `9 / 16`。
- [ ] 画面放大或缩小时不发生拉伸，且不会遮挡右侧参数面板或下方时间轴。
- [ ] 选中特效后，画布选区仍准确覆盖特效在预览画面中的位置。
- [ ] 在窄窗口和较宽窗口下都不会出现异常溢出或被裁切。

## Out of scope

- 修改视频导出分辨率或导出编码。
- 增加新的视频画布比例设置。
- 重新设计整个编辑器的配色和品牌视觉。

## Related implementation concepts

- `PreviewPlayer`：浏览器预览入口。
- `EditorComposition`：预览和导出共用的组合定义。
- `ProjectSettings.width` / `ProjectSettings.height`：编辑项目画布尺寸。

## Initial triage notes

已检查预览组件、共享 Remotion 组合定义及编辑器 CSS。当前确实存在固定竖屏预览外壳；具体“小框”是否还叠加了素材比例、Player 内层尺寸或浏览器窗口因素，需要在本地页面导入实际视频后复现确认。
