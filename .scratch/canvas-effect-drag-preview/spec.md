# 实时预览中的特效拖拽过程反馈

Status: resolved

## Problem Statement

用户在实时预览画布中拖动已选中的特效位置或缩放特效时，当前界面只在鼠标松开后才更新结果。拖动过程中实际特效画面、特效选区和右侧参数面板都不会跟随变化，用户无法判断特效最终会落在哪里或缩放到什么大小。

## Solution

为实时预览画布增加“过程预览”：用户按住已选中特效并拖动位置或四角缩放手柄时，实际特效画面、选区和右侧位置/尺寸参数立即随操作实时变化。页面层统一维护拖动期间的临时项目快照，实时预览、选区和属性面板共同消费该快照；用户松开鼠标后，页面层只提交一次最终参数变更，使一次完整拖拽对应一次编辑历史。

特效的位置和尺寸继续受到画布边界及最小尺寸约束。当前版本不增加辅助线、吸附、`Esc` 取消或方向键微调。

## User Stories

1. 作为特效编辑者，我希望拖动已选中特效的位置时，实际特效画面立即跟随鼠标，以便判断特效放置到哪里合适。
2. 作为特效编辑者，我希望拖动特效时选框与实际特效保持一致，以便持续确认当前选中的区域。
3. 作为特效编辑者，我希望拖动特效时右侧位置参数实时变化，以便同时获得视觉和数值反馈。
4. 作为特效编辑者，我希望拖动特效时位置不会超出画布边界，以便松开鼠标后仍得到合法布局。
5. 作为特效编辑者，我希望拖动特效四角缩放手柄时实际特效立即改变大小，以便准确判断最终尺寸。
6. 作为特效编辑者，我希望缩放时选框和实际特效保持一致，以便清楚识别当前尺寸范围。
7. 作为特效编辑者，我希望缩放时右侧宽度和高度参数实时变化，以便进行精确调整。
8. 作为特效编辑者，我希望特效缩放不会小于允许的最小尺寸，也不会超出画布，以便避免无效或不可见的特效布局。
9. 作为特效编辑者，我希望拖动过程中时间轴和其他编辑状态继续保持稳定，以便过程预览不会意外改变特效片段的时间范围。
10. 作为特效编辑者，我希望鼠标松开后才正式保存位置或尺寸变化，以便拖动中间的每一帧不会单独写入项目历史。
11. 作为特效编辑者，我希望一次完整拖动只产生一条编辑历史，以便使用 `Ctrl+Z` 一次撤销整次位置移动或缩放。
12. 作为特效编辑者，我希望没有实际发生位置或尺寸变化时不产生历史记录，以便撤销栈不出现无效操作。
13. 作为特效编辑者，我希望拖动后重新查看项目时，最终位置和尺寸仍与过程预览的结果一致，以便确认编辑结果已正式保存。
14. 作为编辑者，我希望实时预览、特效选区和属性面板共享同一份临时结果，以便三处界面不会显示互相矛盾的状态。
15. 作为编辑者，我希望过程预览不使用额外缓动或吸附，以便特效位置和尺寸直接对应当前鼠标位置。

## Implementation Decisions

- 页面层继续作为已提交编辑项目、选中状态和临时编辑状态的协调边界；画布交互组件只报告用户手势产生的临时位置和尺寸，不直接修改持久化项目或编辑历史。
- 采用“手势开始记录基准、手势期间生成临时项目快照、手势结束提交最终参数”的状态模型。临时快照在手势期间驱动实时预览、特效选区和属性面板。
- 位置拖动和四角缩放使用同一个临时项目快照通道，确保两种操作在反馈和提交语义上保持一致。
- 临时位置和尺寸必须经过现有的边界、最小尺寸和数值归一化规则；位置不能使特效超出画布，宽高不能低于既有最小值。
- 鼠标移动期间只更新页面层临时状态，不派发正式编辑命令、不触发项目历史写入，也不把中间状态当作独立自动保存结果。
- 鼠标松开时比较最终位置/尺寸与手势开始值；只有实际发生变化时才派发一次原子化参数更新命令。
- 一次位置拖动或缩放对应一条编辑历史。顶部撤销按钮和 `Ctrl+Z` 继续复用现有编辑器历史机制，并一次恢复整次手势前的参数。
- 取消本次拖动不新增专门的 `Esc` 行为；当前版本仅以鼠标松开作为手势结束入口。
- 右侧属性面板读取页面层当前可见项目，因此拖动期间显示临时位置和尺寸，手势结束后自然切换为已提交项目中的最终值。
- 时间轴片段的起止帧、特效轨道布局、播放头和导出协议不因本功能改变；本功能只调整特效参数中的位置和尺寸反馈。
- 不增加画布辅助线、边缘/中心吸附或键盘方向键微调。
- 复用现有预览与导出共用的特效模板渲染定义，过程预览不维护第二套特效视觉实现。

## Testing Decisions

- 测试应验证用户可观察的外部行为：拖动中的特效画面、选区、位置/尺寸参数、最终项目参数和撤销结果；不锁定临时状态使用 `ref`、事件监听器数量或具体组件内部实现。
- 在页面层统一临时快照接缝测试：位置拖动过程中实时项目、预览输入、选区和属性面板反映相同的临时位置；缩放过程中反映相同的临时宽高。
- 在位置拖动行为测试：按下、移动、连续移动和松开后，特效位置按画布比例更新；位置始终被限制在画布内；无移动的手势不提交参数命令。
- 在缩放行为测试：四个角的缩放都能实时改变实际尺寸和选区；宽高保持最小尺寸约束；缩放结果不会超出画布；无尺寸变化的手势不提交参数命令。
- 在提交与历史测试：鼠标移动期间不产生正式历史；松开后有变化时只产生一次参数更新；`Ctrl+Z` 一次恢复整次拖动前的状态；没有变化时撤销栈不增加无效记录。
- 在共享显示状态测试：拖动期间右侧位置/尺寸参数与预览选区及实际特效一致；手势结束后最终参数仍保持一致。
- 在回归测试：时间轴片段移动、片段裁剪、播放头定位、模板添加、预览播放和导出输入不受画布特效过程预览影响。
- 测试应覆盖没有视频、只有特效、视频与特效同时存在，以及横屏、竖屏和方形画布等现有预览比例。
- 继续复用现有画布选择、预览画布、编辑器页面和编辑器历史测试的夹具与断言风格；新增函数和复杂状态转换使用中文注释说明临时状态与提交状态的区别。

## Out of Scope

- 不实现画布辅助线、中心线、边缘线或吸附。
- 不实现 `Esc` 取消拖动并恢复手势开始状态。
- 不实现方向键或其他键盘方式微调特效位置和尺寸。
- 不实现关键帧、随时间变化的位置或尺寸动画。
- 不改变特效片段的起始帧、持续时间或特效轨道分配。
- 不改变现有特效模板、参数声明、预览与导出共用的视觉实现。
- 不增加新的撤销/重做模型；继续使用现有编辑器历史。
- 不实现拖动过程中的自动保存快照或每帧持久化。
- 不扩展到模板库拖入时间轴的拖放过程；该交互属于另一条功能链路。

## Further Notes

- 领域术语“过程预览”已记录在根目录 `CONTEXT.md`，表示调整特效片段位置或尺寸时，实际画面、选区和相关参数实时同步的反馈。
- 本规格复用现有时间轴实时交互的临时快照和一次性历史提交原则，避免为画布拖拽引入第二套状态语义。
- 当前代码中画布拖动期间的临时值尚未进入预览播放器和属性面板的数据流；实现时应优先打通页面层统一临时项目快照，再补齐组件级行为测试。
- 本规格不要求建立新的 ADR：该交互方案可逆，且没有新的持久化协议或跨上下文架构取舍。
