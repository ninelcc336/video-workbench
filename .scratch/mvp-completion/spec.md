# 模板化视频特效编辑器 MVP 闭环补齐

Status: ready-for-agent

## Problem Statement

当前项目已经具备模板化特效编辑器的主要领域模型、预览、时间轴基础交互、Remotion 导出和本地工作区服务，但关键能力仍停留在局部实现：项目入口固定、个人资产只保存在页面内存、视频片段时长固定为 5 秒、缺失素材无法重新关联、时间轴与预览联动不完整、导出取消未接通。用户可以看到编辑器，但还不能稳定完成“导入素材—编辑—保存—关闭—重新打开—继续编辑—导出”的本地创作闭环。

## Solution

补齐本地优先 MVP 的完整使用闭环。用户可以选择或切换本地工作区，在一个工作区内管理多个编辑项目、视频素材、个人预设和视频模板；导入视频时读取真实元数据，首个视频确定编辑项目的画布比例和帧率，视频片段默认使用源素材完整时长；时间轴、预览和参数面板保持同步；缺失素材可以安全重新关联；所有重要编辑结果自动保存并可恢复；导出任务支持取消、失败重试和结果管理。

本规格继续遵循已有产品边界：单条主视频轨道、多条特效轨道、开发者提供的 2D 特效模板、本地 Web 应用、MP4 导出，以及预览和导出共用同一套 Remotion 特效定义。

## User Stories

1. 作为首次使用者，我希望选择或创建本地工作区，以便明确知道项目和素材保存在哪里。
2. 作为使用者，我希望应用记住上次使用的工作区，以便下次启动后直接继续工作。
3. 作为使用者，我希望切换工作区，以便管理不同主题或不同用途的视频资产。
4. 作为使用者，我希望切换工作区前看到未保存提示，以便避免丢失当前编辑结果。
5. 作为使用者，我希望看到工作区中的编辑项目列表，以便找到以前的作品。
6. 作为使用者，我希望创建命名的编辑项目，以便同时管理多个视频作品。
7. 作为使用者，我希望打开、重命名、复制和删除编辑项目，以便管理项目生命周期。
8. 作为使用者，我希望删除编辑项目时不会误删其他项目仍引用的视频素材，以便保护本地资产。
9. 作为使用者，我希望编辑操作后自动保存，以便刷新或关闭应用后仍能恢复成果。
10. 作为使用者，我希望看到已保存、保存中和保存失败状态，以便判断当前成果是否安全。
11. 作为使用者，我希望保存失败后可以重试，而不是静默丢失编辑结果。
12. 作为使用者，我希望项目文件损坏时可以从最近备份恢复，以便尽量找回成果。
13. 作为使用者，我希望旧版本项目可以自动迁移，以便应用升级后仍能打开以前的作品。
14. 作为使用者，我希望项目读取失败时看到错误和恢复选项，而不是被静默带到一个空编辑项目。
15. 作为使用者，我希望导入视频时看到文件名、格式、大小、时长、分辨率和帧率，以便确认素材是否正确。
16. 作为使用者，我希望非视频文件、损坏文件或无法读取元数据的文件在导入阶段被拒绝，以便项目不会进入不可导出状态。
17. 作为使用者，我希望导入视频时看到处理状态，以便知道大文件是否仍在处理中。
18. 作为使用者，我希望首个视频素材自动决定项目画布比例和帧率，以便预览和导出符合视频内容。
19. 作为使用者，我希望新建视频片段默认使用源视频完整时长，以便长视频不被截断、短视频不产生超出素材的空白。
20. 作为使用者，我希望后续导入的视频适配现有编辑项目，而不会偷偷改变已有画布和时间基准。
21. 作为使用者，我希望素材缺失时项目仍能打开并明确标记缺失的视频片段，以便先处理项目结构。
22. 作为使用者，我希望通过选择本地文件重新关联缺失素材，以便恢复预览和导出。
23. 作为使用者，我希望替换为其他视频文件时看到二次确认、时长风险和内容变化提示，以便避免误替换。
24. 作为使用者，我希望重新关联操作支持撤销，以便可以恢复替换前的素材引用。
25. 作为使用者，我希望查看素材引用关系，以便知道删除素材会影响哪些编辑项目。
26. 作为使用者，我希望重命名素材只改变显示名称，不改变项目中的稳定素材引用。
27. 作为使用者，我希望未被引用的素材可以安全移除，以便控制工作区占用空间。
28. 作为使用者，我希望点击时间轴标尺或空白区域定位播放头，以便快速查看指定时间点。
29. 作为使用者，我希望播放头、预览画面和时间显示始终同步，以便知道当前正在编辑哪一帧。
30. 作为使用者，我希望点击视频片段或特效片段后，预览选区和参数面板同步更新，以便准确编辑目标。
31. 作为使用者，我希望拖动视频片段或特效片段改变起始位置，以便调整内容出现的时间。
32. 作为使用者，我希望拖动片段边缘裁剪持续时间，以便控制内容的生效范围。
33. 作为使用者，我希望从模板库拖放特效模板到指定时间点，以便用直观方式添加特效片段。
34. 作为使用者，我希望删除选中的片段后时间轴、预览和参数面板立即同步，以便确认删除结果。
35. 作为使用者，我希望时间轴操作不会产生负帧或零时长片段，以便项目始终保持合法。
36. 作为使用者，我希望重要时间轴操作支持撤销和重做，以便放心尝试不同布局。
37. 作为使用者，我希望一次完整的拖动或裁剪只产生一条历史记录，以便一次撤销即可恢复整个操作。
38. 作为使用者，我希望保存个人预设并在重启后继续使用，以便复用常用的特效参数。
39. 作为使用者，我希望个人预设只保存参数，不复制特效模板实现，以便模板升级仍能保持资产关系。
40. 作为使用者，我希望查看、套用和删除个人预设，以便管理自己的常用配置。
41. 作为使用者，我希望保存视频模板并在重启后继续使用，以便复用整套特效时间轴布局。
42. 作为使用者，我希望套用视频模板时新增特效片段而不覆盖当前项目，以便安全组合不同布局。
43. 作为使用者，我希望一次套用视频模板只产生一条历史记录和一次自动保存，以便可以整体撤销。
44. 作为使用者，我希望视频模板在不同帧率项目中保持原来的秒数位置和持续时间，以便模板节奏不发生变化。
45. 作为使用者，我希望模板套用时自动避让已有特效轨道，以便新增片段不会互相遮挡。
46. 作为使用者，我希望套用超出当前视频时长的模板时收到提示，以便知道还需要调整视频或特效范围。
47. 作为使用者，我希望导出前看到当前项目存在的缺失素材或无效状态，以便在渲染失败前修复问题。
48. 作为使用者，我希望导出任务显示准备中、渲染中、已完成、失败或已取消状态，以便了解处理进度。
49. 作为使用者，我希望准备中或渲染中可以取消导出，以便及时停止错误任务。
50. 作为使用者，我希望导出失败后可以重新发起任务，并保留原编辑项目，以便继续修复问题。
51. 作为使用者，我希望成功导出后看到文件名、大小、生成时间和可用的打开入口，以便找到最终视频。
52. 作为使用者，我希望多次导出不会无提示覆盖旧文件，以便保留不同导出结果。
53. 作为使用者，我希望导出 MP4 与浏览器预览在画面、特效时间、参数和原始音频上保持一致，以便最终文件符合编辑时看到的结果。

## Implementation Decisions

- 以工作区适配器作为本地资产和项目持久化的主要边界，统一承载工作区切换、项目列表、项目读写、备份恢复、视频素材元数据、素材重新关联、个人预设和视频模板仓储能力。
- 以编辑器状态和命令接口作为编辑行为的主要边界。时间轴、画布和属性面板只提交用户意图，不直接修改项目数组；拖动、裁剪、模板套用和素材重新关联使用原子化命令进入历史。
- 保留现有的单主视频轨道和多条特效轨道模型。视频片段表示视频素材在主视频轨道上的一次使用，视频素材本身可以被多个编辑项目引用。
- 视频导入必须读取可用的真实元数据，包括时长、分辨率和帧率；元数据读取失败时拒绝创建视频片段。服务端和浏览器都不得仅凭文件扩展名判断素材可用性。
- 空编辑项目加入第一个视频片段时，以首个视频素材确定项目画布比例和帧率。后续视频素材不自动改变项目设置；无法读取帧率时回退到 30fps并提示用户。
- 新建视频片段默认使用源视频完整时长，并按主视频轨道末尾追加。裁剪命令必须保证非负起点和正整数持续帧数。
- 缺失素材保持为可恢复的项目状态。重新关联允许选择不同文件，但必须进行二次确认，提示时长不匹配风险，并把替换作为可撤销操作；重新关联不得自动改变项目画布或特效布局。
- 素材删除前必须检查跨项目引用关系。被引用的素材不能直接删除；未被引用的素材可以移除，删除项目也不得级联删除共享素材。
- 自动保存使用防抖调度，并向界面暴露保存状态。保存使用临时文件替换正式文件，保留一个最近备份；保存或读取失败时不得静默创建空编辑项目或覆盖原文件。
- 通过项目数据的 `schemaVersion` 处理向前迁移。迁移失败时保留原始项目文件，并提供从备份恢复的入口。
- 个人预设和视频模板必须持久化到当前工作区，支持保存、列表展示、套用和删除。模板版本不兼容时提示用户并使用安全的默认参数兜底。
- 视频模板保存特效片段相对时间轴布局，不保存视频素材。套用模板时以目标播放头为起点新增片段，跨帧率套用按秒数换算起点和持续时间，再保存为当前项目的整数帧。
- 一次视频模板套用必须作为一个编辑命令进入历史，并自动为新增片段选择不会遮挡已有片段的特效轨道。
- 时间轴操作必须驱动同一个当前帧状态，保持时间轴、Remotion Player、画布选区和属性面板同步。鼠标拖动期间允许使用临时快照，松开后只提交一次正式命令。
- 渲染任务继续使用项目快照，并通过现有任务状态接口支持取消、失败重试和结果查询。每次导出使用不冲突的输出文件名，完成后暴露文件元数据和打开入口。
- 预览和导出继续共用同一套 Remotion 特效定义、参数规范化逻辑和编辑项目数据。首批模板必须有浏览器预览和 MP4 导出的代表性画面回归基准。

## Testing Decisions

- 测试关注用户可观察行为和领域不变量，不测试组件内部实现细节或具体 CSS 结构。
- 工作区测试覆盖创建和切换工作区、多个项目的创建/列表/打开/复制/重命名/删除、原子保存、备份恢复、schemaVersion 迁移和读取失败保护。
- 素材测试覆盖视频元数据读取、完整时长导入、首个视频的画布/帧率匹配、格式拒绝、缺失检测、重新关联、跨项目引用保护、重命名和安全删除。
- 编辑器领域测试覆盖时间轴定位、片段移动、边缘裁剪、删除、模板拖放、临时预览提交、原子撤销重做、自动轨道分配、视频模板一次性套用和跨帧率换算。
- 预设与视频模板测试覆盖持久化、列表、套用、删除、参数深拷贝、模板版本不兼容处理和不同项目帧率下的时间保持。
- 渲染测试覆盖任务取消、失败重试、输出文件不覆盖、缺失素材阻止导出、任务状态转换和结果文件可访问性。
- React 组件测试沿用当前测试方式，验证时间轴、预览、参数面板、工作区选择器、项目管理界面、资产管理界面和导出状态的外部交互。
- 端到端测试覆盖新用户从选择工作区、导入真实视频、排列片段、添加和调整多个特效、保存个人预设、保存视频模板、关闭后重新打开、重新关联缺失素材到导出 MP4 的完整流程。
- 代表性模板至少覆盖信息叠加、装饰动画和片段转场，并比较预览与导出的关键帧、画面比例、特效出现时间和原始音频时长。
- 现有 `npm test`、类型检查和生产构建必须继续通过；浏览器端验收应在可用的 Playwright 浏览器环境中执行，而不能只依赖静态测试。

## Out of Scope

- 云端存储、账号体系、多人协作和跨设备同步。
- AI 自然语言生成、AI 推荐和自动剪辑。
- 自动字幕、配音、音乐编辑、独立音频轨道、音量曲线和音频转场。
- 多视频轨道、复杂剪辑、关键帧、表达式编辑和自定义动画逻辑。
- 3D、WebGL、复杂粒子引擎、抠像和高级色彩管理。
- 高级编码器、码率、编码参数和批量导出队列。
- 桌面安装包、云端渲染和完整的项目版本历史。
- 基于镜头、语音、人脸或语义的自动模板适配。

## Further Notes

- 本规格将当前已确认的 MVP 决策集中成一个可执行范围，不代表所有功能必须在一个提交中完成；实现时应优先完成“工作区/项目恢复—素材元数据—时间轴联动—资产持久化—导出闭环”的顺序。
- 当前项目已有部分能力和测试，实施前应先复用现有工作区适配器、编辑器命令、渲染任务和组件测试边界，避免重复建立平行状态或第二套预览逻辑。
- 规格遵循本项目的领域词汇：源文件称为“视频素材”，放入编辑项目后的时间轴记录称为“视频片段”，渲染过程称为“导出任务”。
- 项目已有本地优先、MP4 为主要产物、单主视频轨道、多条特效轨道、参数化个人预设、视频模板时间轴布局、预览与导出共用 Remotion 定义等 ADR；本规格补充其尚未完成的产品闭环。
