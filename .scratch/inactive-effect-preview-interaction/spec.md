# 特效未生效时间段的预览交互限制

Status: ready-for-agent

## Problem Statement

用户在实时预览中选中特效后，即使当前播放头不在该特效片段的生效时间段内，预览画布仍然显示可拖拽的特效选区。此时实际特效画面并未出现，用户无法判断拖拽目标和最终位置，容易误操作。

## Solution

根据当前播放头是否处于特效片段的生效时间段，控制实时预览画布中的特效选区交互：当播放头位于生效区间内时，继续显示选区并允许拖动位置或缩放；当播放头位于生效区间外时，隐藏选区并禁止在预览画布中拖拽该特效。

特效在未生效时间段仍保持选中状态，时间轴和右侧参数面板仍可继续编辑其时间范围及参数。播放头回到生效区间后，选区应自动恢复显示并继续支持拖拽。

## User Stories

1. 作为特效编辑者，我希望只有在特效实际出现在预览画面时才能拖动它，以便明确知道当前正在调整的对象。
2. 作为特效编辑者，我希望播放头位于特效生效区间内时仍能拖动特效位置，以便继续完成画布编辑。
3. 作为特效编辑者，我希望播放头位于特效生效区间内时仍能缩放特效，以便继续调整特效尺寸。
4. 作为特效编辑者，我希望播放头位于特效生效区间外时预览画布不显示误导性的特效选区，以便区分“已选中”和“当前可操作”。
5. 作为特效编辑者，我希望特效未生效时仍保留时间轴选中状态，以便知道当前正在编辑哪个特效片段。
6. 作为特效编辑者，我希望特效未生效时仍能使用右侧参数面板调整参数，以便不必先定位播放头才能修改数值。
7. 作为特效编辑者，我希望播放头回到特效生效区间后选区自动恢复，以便继续使用预览画布调整特效。
8. 作为特效编辑者，我希望特效在生效区间的起始帧可以立即操作，以便不需要多播放一帧才能开始编辑。
9. 作为特效编辑者，我希望特效在生效区间结束帧不再显示可拖拽选区，以便交互边界与实际生效边界一致。
10. 作为编辑者，我希望该限制不改变特效片段的时间范围、位置参数或尺寸参数，以便本次优化只调整预览交互反馈。

## Implementation Decisions

- 使用特效片段的时间范围和当前播放帧判断“生效状态”：起始帧包含在内，结束帧不包含在内。
- 预览画布及其选区组件共享同一个生效状态判断，避免选区可见性和拖拽能力出现不一致。
- 生效状态为真时，保留现有过程预览能力：位置拖动、四角缩放、边界限制、属性面板同步和一次性历史提交均不改变。
- 生效状态为假时，不渲染预览画布中的可交互特效选区；因此画布不会响应该特效的位置拖动或缩放手势。
- 未生效不等于未选中：时间轴和右侧参数面板继续显示并操作当前选中特效。
- 播放头变化只影响预览选区是否可见和可操作，不修改编辑项目、不进入编辑历史，也不改变特效片段的时间范围。
- 不新增辅助线、吸附、禁用右侧参数控件、自动跳转播放头或新的撤销行为。
- 继续复用预览和导出共用的特效模板定义，不维护第二套时间判断或视觉实现。

## Testing Decisions

- 测试验证用户可观察行为：选区可见性、画布拖拽回调、时间轴选中状态、属性面板可编辑性和播放头跨越边界后的恢复行为。
- 在 `PreviewCanvas` / `CanvasSelection` 接缝测试：生效区间起始帧显示选区并允许操作，生效区间内部显示选区并允许操作，结束帧及区间外隐藏选区且不触发拖拽回调。
- 测试播放头从生效区间外进入区间时选区恢复，从区间内离开区间时选区消失。
- 测试特效未生效时右侧参数面板仍能提交参数变化，且不会因为预览选区隐藏而改变项目时间范围。
- 测试现有生效区间内的位置移动和四角缩放回归通过，确保本次门控不破坏过程预览、边界限制和一次性历史提交。
- 测试应通过公开组件行为和回调观察结果，不依赖内部状态、DOM 事件监听器数量或具体实现变量。
- 继续复用现有预览画布、画布选区、属性面板和编辑器页面测试夹具；新增函数及时间边界判断使用中文注释。

## Out of Scope

- 不改变特效片段的起始帧、持续时间或时间轴轨道布局。
- 不禁用特效未生效时的右侧参数面板和时间轴编辑。
- 不自动将播放头跳转到特效片段的起始帧。
- 不增加“当前特效未生效”的额外提示、气泡或空状态文案；本次以隐藏预览选区作为反馈。
- 不实现关键帧或参数随时间变化的编辑。
- 不改变预览与导出的渲染定义和项目数据结构。

## Further Notes

- 本规格补充 `.scratch/canvas-effect-drag-preview/spec.md` 中已经完成的特效过程预览能力，重点解决“已选中但当前不可见仍可拖拽”的交互边界。
- 该功能不需要新的 ADR：它是可逆的预览交互门控，不引入新的持久化协议或跨模块架构取舍。
