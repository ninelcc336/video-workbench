# 隔离视频工作区

Status: ready-for-agent

## Problem Statement

现有“编辑项目 + 固定项目库 + 共享素材”模型把存储管理和创作边界混在一起。用户制作视频 A 时，需要随时创建视频 B 并在两者间切换，且不希望 B 的素材、时间轴或删除操作影响 A。

## Solution

以视频工作区作为唯一的用户可见创作单位。每个工作区独立保存时间轴、特效、设置、视频素材和导出结果；用户可以新建、切换、重命名和删除工作区，但不能选择底层目录。导入到工作区 B 的素材绝不出现在工作区 A，删除或重新关联只影响当前工作区。

## Decisions

- 用户可见术语统一为“视频工作区”；不显示或使用“编辑项目”“本地项目库”及“共享素材”。
- 每个工作区拥有自己的媒体目录和导出目录，素材 ID 只在该工作区内有效。
- 迁移既有数据时，一个被多个旧编辑项目引用的素材复制到每个对应工作区；迁移失败保留原数据并显示可恢复错误。
- 工作区切换前，只有自动保存进行中或失败时才要求确认；正常已保存状态可直接切换。
- 个人预设与视频模板不属于本次范围。

## Acceptance

- 用户可在不接触目录的前提下创建、命名、切换、重命名和删除视频工作区。
- 在工作区 B 导入、重命名、重新关联或删除素材不会改变工作区 A 的素材列表、时间轴或导出结果。
- 关闭并重启应用后，A 与 B 都能恢复到各自最近保存的状态。
- 旧编辑项目与素材可安全迁移，迁移后不保留跨工作区的素材引用。
- 全量单元测试、类型检查、构建和真实浏览器端到端验收通过。

## Out of Scope

- 工作区之间共享、复用或移动视频素材。
- 用户选择、切换或浏览底层存储目录。
- 个人预设与视频模板。
