# 实时预览区域左右边框拖拽调宽

Status: resolved

## Problem Statement

当前编辑器三栏布局中的素材库、实时预览和特效参数面板使用固定的左右栏宽度。用户希望通过鼠标拖拽素材库右边框或特效参数面板左边框，临时调整两侧面板宽度，从而放大或缩小实时预览区域。

## Solution

在素材库右边框和特效参数面板左边框提供通用命中区域。用户按住任一边框横向拖拽时，对应面板宽度连续跟随鼠标变化，实时预览区域同步反向变化。

实时预览区域宽度不得小于编辑主区域宽度的 40%；素材库宽度不得小于 220px；特效参数面板宽度不得小于 230px。拖拽不使用吸附或缓动，布局调整只在当前页面会话中生效，不进入编辑器撤销/重做、不触发项目自动保存，也不持久化到本地工作区。

## User Stories

1. 作为编辑者，我希望拖拽素材库的右边框调整素材库宽度，以便获得更大的实时预览区域。
2. 作为编辑者，我希望拖拽特效参数面板的左边框调整参数面板宽度，以便获得更大的实时预览区域。
3. 作为编辑者，我希望鼠标靠近边框时看到 `col-resize` 光标和轻微高亮，以便知道边框可拖拽。
4. 作为编辑者，我希望拖拽时宽度连续实时变化，以便准确控制三栏布局。
5. 作为编辑者，我希望实时预览区域不小于编辑主区域的 40%，以便预览画面始终保持可用。
6. 作为编辑者，我希望两侧面板分别保持最小可用宽度，以便内容不会被压缩到无法操作。
7. 作为编辑者，我希望布局调整不会污染编辑器历史、自动保存或编辑项目数据。
8. 作为编辑者，我希望调整后的宽度在当前页面会话中保持，刷新页面后恢复默认布局。

## Implementation Decisions

- 复用现有三栏 CSS Grid；初始宽度继续使用素材库 280px、特效参数面板 288px。
- 素材库右边框和特效参数面板左边框各自提供较宽的通用鼠标命中区域，不要求命中 1px 视觉边线。
- 使用 Pointer Events 处理横向拖拽；本功能不增加键盘调整入口。
- 左右面板独立调整；拖动任一边框只改变对应侧面板宽度，另一侧保持当前宽度。
- 素材库最小宽度为 220px，特效参数面板最小宽度为 230px，实时预览区域最小宽度为编辑主区域的 40%。
- 宽度按连续像素变化，不使用吸附、固定步长或动画缓动。
- 布局宽度保存在页面 React 状态中，不进入 EditorStore、不触发自动保存、不写入项目历史或本地工作区。
- 浏览器窗口或编辑主区域尺寸变化时保留当前会话宽度，并重新按约束收紧；低于约 900px 时不额外提供移动端三栏折叠布局。
- 由于两侧面板最小宽度与预览 40% 下限合计至少需要 750px，三栏布局将 750px 作为最小支持宽度；更窄窗口不保证三栏内容完整同时可见。
- 该功能只调整编辑器显示布局，不改变编辑项目、预览内容、时间轴和导出协议。

## Testing Decisions

- 在布局计算公开接缝测试左右面板拖拽结果、最小面板宽度、预览 40% 下限和窗口缩放后的约束收紧。
- 在编辑器页面接缝测试两个边框的可访问名称、鼠标拖拽后的 CSS 布局宽度、左右独立调整和释放后的稳定结果。
- 测试布局调整不会调用编辑器命令，也不会改变项目快照或编辑历史。
- 测试默认宽度保持 280px / 288px，刷新页面重新挂载后恢复默认值。
- 测试函数和复杂布局约束使用中文注释说明面板宽度与编辑项目状态的区别。

## Out of Scope

- 不增加键盘方向键、Home/End 或其他无鼠标布局调整。
- 不增加布局宽度持久化、用户偏好存储或跨页面恢复。
- 不增加移动端抽屉、面板折叠或响应式三栏重排。
- 不改变时间轴高度拖拽和时间轴交互。
- 不把布局调整记录为编辑项目历史。
- 不改变实时预览播放器、特效参数、时间轴片段或导出行为。
