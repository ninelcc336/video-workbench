# 本地模板化视频特效编辑器设计

状态：已确认
日期：2026-07-17

## 1. 产品目标

这是一个面向自媒体剪辑新手的本地 Web 应用。用户通过可视化模板库、时间轴、视频预览和参数面板，为视频添加类似 Remotion 的视觉特效，并导出可发布的 MP4。

首个版本的核心成功标准是：用户无需写代码或查 Remotion 文档，能在 10 分钟内完成导入视频、排列片段、添加 2–3 个特效、调整参数、保存个人预设并导出 MP4，且预览与导出结果基本一致。

## 2. 明确范围

### MVP 包含

- 本地工作区，不要求上传云端。
- 浏览器访问的本地 Web 应用，不制作桌面安装包。
- 多个视频素材在一条主视频轨道上排列。
- 视频片段的导入、排序、裁剪和删除。
- 多条特效轨道。
- 特效片段的拖入、移动、缩放时长和删除。
- 卡片、标签、重点词、提示框等信息叠加模板。
- 气泡、粒子、线条、光效等装饰动画模板。
- 淡入淡出、推入、擦除、缩放等片段转场模板。
- 画布直接拖拽和缩放，以及右侧精确参数面板。
- 参数声明自动生成控件。
- 个人预设和视频模板。
- 基础撤销、重做和关键操作后的自动保存。
- 原始视频音频随片段裁剪、移动和导出。
- MP4 导出、竖屏/横屏/方形预设和 30fps。
- Remotion Player 预览与本地 Remotion 导出共用同一套特效定义。

### MVP 不包含

- 云端存储、账号和多人协作。
- AI 自然语言生成或推荐。
- 自动字幕、配音、音乐编辑和独立音频轨道。
- 多视频轨道、复杂剪辑和关键帧。
- 3D、WebGL 和复杂粒子引擎。
- 高级编码器、码率和色彩管理设置。
- 在网站内自由组合动画逻辑、编写表达式或创建新的视觉逻辑。

## 3. 用户流程

1. 用户选择或创建本地工作区。
2. 导入多个视频素材，素材进入工作区并显示在素材库。
3. 将视频素材拖入一条主视频轨道，完成排序、裁剪和删除。
4. 从左侧模板库查看动效预览，将模板拖到目标时间段，形成特效片段。
5. 选中特效片段后，在画布中直接拖拽或缩放；需要精确控制时使用右侧参数面板。
6. 修改文字、颜色、尺寸、位置、动画方向和动画时长等参数。
7. 通过 Remotion Player 预览结果；编辑器自动保存，并支持撤销和重做。
8. 将当前特效参数保存为个人预设，或将整套时间轴布局保存为视频模板。
9. 选择导出规格并由本地 Remotion 渲染 MP4。

主交互是“模板拖到时间轴”；“移动播放头后点击添加”可以作为辅助入口。

## 4. 总体架构

采用本地模块化 Web 应用：

- 前端：React、TypeScript、Vite。
- 本地服务：Node.js，负责工作区文件操作和渲染任务编排。
- 视频运行时：Remotion Player 用于交互式预览，Remotion 用于最终渲染。
- 持久化：本地工作区中的 JSON 和媒体文件。
- 视觉实现：React、Remotion、CSS 和 SVG 的 2D 动画。

模块职责：

### 编辑器核心

管理编辑项目状态、选中对象、时间轴操作、命令、撤销重做和自动保存。UI 只能通过编辑命令修改项目，不直接修改底层对象。

建议保持一个小接口：提交命令、读取当前快照、订阅状态变化、执行撤销/重做。复杂的状态转换和校验隐藏在模块内部，便于测试和未来替换 UI。

### 特效模板注册表

提供模板的身份、版本、分类、名称、动效预览、参数声明和 Remotion 视觉实现。模板声明参数的名称、类型、默认值、范围和可选值，编辑器据此自动生成控件。

### 预览运行时

接收编辑器核心输出的项目快照，使用 Remotion Player 播放主视频、音频和特效组合。预览不维护第二套动画逻辑。

### 本地工作区适配器

负责创建工作区、导入媒体、读写项目 JSON、保存个人预设和视频模板、列出导出结果。未来云端化时，这里是优先替换的 Adapter seam。

### 渲染适配器

把项目快照转换为 Remotion 渲染输入，管理本地渲染任务的状态、日志、取消和结果路径。预览与导出共用模板注册表和项目模型。

## 5. 数据模型

### 编辑项目

- `schemaVersion`：项目数据版本。
- `settings`：宽度、高度和帧率。
- `videoClips`：视频素材 ID、时间轴开始帧、源素材开始帧、持续帧数和音频状态。
- `effectClips`：特效模板 ID、模板版本、所在轨道、开始帧、持续帧数和参数值。
- `export`：导出格式和规格。

时间统一以帧保存，不以浮点秒数保存。首版特效参数在整个特效片段内保持不变，不保存关键帧。

### 特效模板

特效模板是开发者提供的可复用视觉资产，包含：

- 稳定 ID 和版本号。
- 类型分类和动效预览。
- 参数声明。
- Remotion 视觉实现。

### 个人预设

个人预设只保存某个特效模板的参数配置和用户名称，不复制模板实现。模板升级时，旧预设保留原版本引用，无法兼容时使用默认值并提示用户。

### 视频模板

视频模板保存可复用的时间轴布局，包括特效片段的相对位置、顺序、持续时间和默认参数，不绑定具体视频文件。首版要求新视频的结构和时长大致相近，用户负责手动微调。

## 6. 本地工作区

建议目录结构：

```text
我的视频特效工作区/
├─ projects/
├─ media/
├─ presets/
├─ video-templates/
└─ renders/
```

导入的视频复制到工作区，避免项目依赖临时文件路径。项目保存失败时，保留内存状态并提示工作区不可写；写入时采用临时文件再替换正式文件，避免中途写入损坏项目。

## 7. 界面设计

采用标准三栏布局：

- 左侧：素材库和特效模板库，模板以短动画预览为主要发现方式。
- 中间：视频预览画布，支持特效选区的拖拽和缩放。
- 右侧：选中对象的参数面板，提供精确的文字、颜色、尺寸、位置和动画设置。
- 底部：横跨全宽的时间轴，包含主视频轨道和多条特效轨道。

设计原则是“看到效果再选择”：模板名称和描述是辅助信息，动效预览是主要入口。界面不要求用户理解 Remotion、动画函数或代码。

## 8. 导出与错误处理

首版导出 MP4，默认继承第一个视频片段的分辨率和帧率，并提供：

- 竖屏：1080×1920。
- 横屏：1920×1080。
- 方形：1080×1080。
- 常用帧率：30fps。

渲染状态包括准备中、渲染中、已完成、失败和已取消。视频格式不支持时在导入阶段提示；素材丢失时项目仍可打开但标记为缺失；模板参数异常时使用模板默认值兜底；渲染失败时保留项目并显示失败阶段和日志摘要。

## 9. 验证策略

- 编辑器核心测试时间轴排列、裁剪、特效添加、参数修改、撤销重做和视频模板套用。
- 模板系统测试参数声明、默认值、范围校验和版本兼容。
- 每个模板至少做一次浏览器预览和 MP4 导出冒烟测试。
- 工作区测试保存、重新打开、自动保存、素材缺失和导入复制。
- 端到端测试完整的十分钟创作闭环。
- 对代表性模板保存少量渲染基准帧，检查预览与导出的关键画面一致。

## 10. 分阶段实现建议

### 阶段一：验证渲染闭环

搭建 React/Vite、Node 和 Remotion；完成一个视频素材、一个卡片模板、Remotion Player 预览和 MP4 导出。先证明“同一项目数据可以预览和导出”。

### 阶段二：完成最小编辑器

加入工作区、多个视频片段主轨道、裁剪排序、特效轨道、拖拽添加、基础时间轴和参数面板。

### 阶段三：提升可用性

加入画布直接操作、模板动效预览、撤销重做、自动保存、素材缺失提示和导出状态。

### 阶段四：形成个人资产系统

加入个人预设、视频模板、模板版本、工作区项目列表和常用导出预设。

### 阶段五：模板扩充与验证

补齐三类首批模板，使用真实视频完成端到端验收，再决定是否进入云端化或 AI 推荐阶段。

## 11. 明确的未来扩展点

- 将本地工作区适配器替换为云端存储适配器。
- 将本地渲染适配器替换为云端渲染任务适配器。
- 在现有模板注册表上增加 AI 搜索和推荐。
- 在不破坏现有项目模型的前提下增加关键帧、字幕和独立音频轨道。
- 使用 Tauri 或 Electron 将本地 Web 应用封装为桌面应用。
